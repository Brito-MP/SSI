#1 Capability Leaking

2. 

O programa apresenta uma vulnerabilidade de capability leaking porque abre a diretoria /root
enquanto ainda está a executar com privilégios de root, devido ao bit setuid.

O file descriptor obtido com open("/root", O_RDONLY) fica aberto e é herdado pela shell
lançada com execve("/bin/sh", ...).

Apesar de o programa executar setuid(getuid()) antes de abrir a shell, apenas remove 
os privilégios do processo. O problema é que o file descriptor para /root já tinha sido aberto 
anteriormente com privilégios de root e continua disponível na shell.

Assim, um utilizador normal consegue aproveitar esse file descriptor para aceder a uma diretoria 
protegida, neste caso /root.


3. 

-- exploit_root_fd.c.

Este programa recebe como argumento o número do file descriptor deixado
aberto pelo programa vulnerável. Depois usa fdopendir(fd) para transformar esse file descriptor 
numa diretoria e lista o seu conteúdo com readdir().

Comandos utilizados:

gcc -o exploit_root_fd exploit_root_fd.c
./backupssi
./exploit_root_fd 3

O número 3 deve ser substituído pelo file descriptor mostrado no output do programa backupssi

Desta forma, mesmo sendo um utilizador normal, é possível aceder indiretamente ao conteúdo da 
diretoria /root através do file descriptor herdado.


4.
-- backupssi_fixed.c.

A correção consiste em fechar o file descriptor da diretoria /root antes de lançar a shell.

No programa corrigido é executado:

close(dfd);

antes de execve("/bin/sh", ...).

Assim, o acesso à diretoria /root, que tinha sido obtido com privilégios de root, não é 
herdado pelo  utilizador normal. Como esse recurso deixa de estar disponível, a shell 
já não consegue usá-lo para aceder indiretamente a /root.

#2  Elevação de Privilégio

2. Análise da vulnerabilidade

A vulnerabilidade está no facto de o programa abrir o ficheiro /etc/passwd com permissões de 
escrita enquanto ainda está a executar com privilégios de root.

Depois disso, o programa executa setuid(getuid()), deixando de correr como root, mas não 
fecha o file descriptor aberto para /etc/passwd.

Quando a shell é aberta com execl("/bin/sh", "sh", NULL), essa shell herda o file descriptor.
Assim, apesar de o utilizador já não ter privilégios de root, continua a conseguir escrever 
em /etc/passwd através desse file descriptor.


3. 

Escrever uma nova entrada no ficheiro /etc/passwd usando o file descriptor herdado pela shell.

Se o programa imprimir:

Passwd FD leaked: 3

pode ser usado o seguinte comando na shell aberta:

echo 'ssihacker::0:0::/root:/bin/sh' >&3

Este comando adiciona ao ficheiro /etc/passwd um novo utilizador chamado ssihacker, 
com UID 0 e GID 0.


4. Implicações práticas

Como o utilizador ssihacker fica com UID 0, passa a ter privilégios equivalentes aos do 
utilizador root.

Depois de adicionar a entrada ao /etc/passwd, é possível tentar iniciar sessão com:

su ssihacker

Se o login for bem-sucedido, o hacker passa a ter uma shell com privilégios de root.

Isto permite executar comandos administrativos, ler e alterar ficheiros protegidos, 
criar ou apagar utilizadores, modificar configurações do sistema e comprometer totalmente a máquina.


5. Correção da vulnerabilidade

A correção consiste em fechar o file descriptor antes de lançar a shell.

No programa corrigido, é executado:

close(fd);

antes de execl("/bin/sh", "sh", NULL).

Assim, a shell já não recebe o acesso de escrita a /etc/passwd e o utilizador normal 
deixa de conseguir alterar esse ficheiro através do programa.
